Self-Healing E2E Testing Pipelines: Marrying Agentic AI with Playwright and GitHub Actions 🌐 🖥️

November 4, 2026

While fidling with the Agentic AI for a while I have tried to build a locator selfhealing Agentic AI. Every automation engineer has lived through the frustration of UI locator drift. A frontend update changes an element ID, reworks a component tree, or swaps an input wrapper, instantly breaking a test suite that was working an hour before.

Rather than treating test fragility as a constant maintenance burden, we can embed Agentic AI reflection loops directly into the Page Object Model (POM) pattern. When an element interaction times out, the framework traps the error, gathers interactive DOM elements, requests a targeted locator from an LLM, and retries the action live without aborting the CI pipeline.

Here is how the end-to-end architecture, directory layout, code modules, and pipeline orchestration come together. This is the new era where AI can automate maintenance and codefix as a tester we should embrace and sustain in the wave of AI Bubble.

1. System Architecture & Logical Topology

The framework divides responsibilities into three isolated tiers: the GitHub Actions runner environment, the Playwright testing harness with page objects, and the self-healing intelligence layer.

3. The Implementation Blueprint

Step A: The Self-Healing Coordinator (utils/self_healer.js)

The self-healer provides an execution wrapper over standard Playwright actions. It first attempts the primary locator with a tight 3-second timeout. If that fails, it scrubs the DOM and initiates a guided retry loop.



import { getHealedSelector } from './ai_client.js';

export class SelfHealer {
    constructor(page) {
        this.page = page;
    }

    // Scrapes interactive nodes while discarding noise like wrapper divs and SVG paths
    async getCleanInteractiveDOM() {
        return await this.page.evaluate(() => {
            const elements = document.querySelectorAll('input, button, select, textarea, a, [role]');
            return Array.from(elements).map(el => {
                const tag = el.tagName.toLowerCase();
                const type = el.getAttribute('type') || '';
                const id = el.id ? ` id="${el.id}"` : '';
                const name = el.getAttribute('name') ? ` name="${el.getAttribute('name')}"` : '';
                const testId = el.getAttribute('data-testid') ? ` data-testid="${el.getAttribute('data-testid')}"` : '';
                const placeholder = el.getAttribute('placeholder') ? ` placeholder="${el.getAttribute('placeholder')}"` : '';
                const aria = el.getAttribute('aria-label') ? ` aria-label="${el.getAttribute('aria-label')}"` : '';

                return `<${tag} type="${type}"${id}${name}${testId}${placeholder}${aria}></${tag}>`;
            }).join('\n');
        });
    }

    // Maps structured JSON responses back to native Playwright selector methods
    resolveLocator(healed) {
        if (healed.selectorType === 'getByTestId') {
            return this.page.getByTestId(healed.value);
        } else if (healed.selectorType === 'getByLabel') {
            return this.page.getByLabel(healed.value);
        } else if (healed.selectorType === 'getByRole') {
            return this.page.getByRole(healed.value);
        }
        return this.page.locator(healed.value);
    }

    async safeFill(locatorPromise, text, fallbackInfo, maxRetries = 3) {
        // 1. Initial attempt with fast timeout
        try {
            await locatorPromise.fill(text, { timeout: 3000 });
            return;
        } catch (error) {
            console.warn(`[Self-Healing] Primary locator failed: ${error.message}`);
        }

        // 2. Self-healing loop with reflection
        let currentError = null;
        const domSnapshot = await this.getCleanInteractiveDOM();

        for (let attempt = 1; attempt <= maxRetries; attempt++) {
            console.log(`[Self-Healing] Attempt ${attempt}/${maxRetries}: Requesting healed locator from LLM...`);

            const healed = await getHealedSelector({
                failedSelector: fallbackInfo.originalSelector,
                actionIntent: fallbackInfo.intent,
                domSnapshot: domSnapshot,
                lastError: currentError
            });

            if (!healed || !healed.value) {
                console.warn(`[Self-Healing] Attempt ${attempt}: Agent returned an invalid response.`);
                continue;
            }

            console.log(`[Self-Healing] Agent proposed: ${JSON.stringify(healed)}`);

            try {
                const healedLocator = this.resolveLocator(healed);
                await healedLocator.fill(text, { timeout: 3000 });
                console.log(`[Self-Healing] Successfully filled field using healed selector on attempt ${attempt}!`);
                return;
            } catch (err) {
                console.warn(`[Self-Healing] Proposed selector failed: ${err.message}`);
                currentError = err.message; // Re-inject failure error for the next agent turn
            }
        }

        throw new Error(`[Self-Healing] Failed to heal locator after ${maxRetries} attempts.`);
    }
}

Step B: The AI Inference Client (utils/ai_client.js)

The AI module constructs an engineering prompt enforcing JSON schema output. It supplies the broken selector, the user’s intent, the interactive DOM snippet, and previous error traces directly to the model.



export async function getHealedSelector({ failedSelector, actionIntent, domSnapshot, lastError }) {
    const prompt = `
You are an expert QA Automation Engineer fixing broken Playwright locators.
The test is trying to fill text into an input field.

Original Locator: ${failedSelector}
Action Intent: ${actionIntent}
${lastError ? `Previous attempt failed with error: ${lastError}` : ''}

Current Page DOM snippet:
${domSnapshot}

Rules:
1. Target ONLY writable text fields (input type="text", "email", textarea, etc.). NEVER pick checkboxes, buttons, or radio buttons for a fill action.
2. The locator MUST resolve to exactly ONE unique element. Prefer unique 'data-testid' (e.g. "input-username") or unique ID.
3. Return ONLY a valid raw JSON object with keys "selectorType" and "value".
   - If using data-testid, use: {"selectorType": "getByTestId", "value": "input-username"}
   - If using id/css, use: {"selectorType": "locator", "value": "#username-input"}
4. Do NOT include markdown code blocks or explanations.
`;

    try {
        const response = await fetch('[http://arul-ms7e27.tail83617f.ts.net:11434/api/generate](http://arul-ms7e27.tail83617f.ts.net:11434/api/generate)', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({
                model: 'llama3.2:3b',
                prompt: prompt,
                stream: false,
                format: 'json'
            })
        });

        if (!response.ok) {
            throw new Error(`Ollama error: ${response.status} ${response.statusText}`);
        }

        const data = await response.json();
        const cleanedResponse = data.response.replace(/```json/gi, '').replace(/```/g, '').trim();
        return JSON.parse(cleanedResponse);

    } catch (err) {
        console.error('[AI Client] Request failed:', err.message);
        return null;
    }
}

The Page Object Model exposes clear business actions (enterUserName), leaving tests clean and readable while routing interactions through the self-healing engine.

    }

}




// pages/fill_pages.js
import { SelfHealer } from '../utils/self_healer.js';

export class FillPage {
    constructor(page) {
        this.page = page;
        this.healer = new SelfHealer(page);
        this.usernameSelector = '#username-input';
    }

    async enterUserName(username) {
        await this.healer.safeFill(
            this.page.locator(this.usernameSelector),
            username,
            {
                originalSelector: this.usernameSelector,
                intent: 'Target the main username text field in the form'
            }
        );
    }
}




// tests/test1_spec.js

    test('should navigate and populate the field', async ({ page }) => {

        await nav.goToPage();
        await expect(page).toHaveURL('[http://127.0.0.1:8000/index.html](http://127.0.0.1:8000/index.html)');

4. The CI/CD Pipeline: GitHub Actions Setup

Running tests against static or mock assets in cloud runners requires hosting the files directly within the runner workspace. To eliminate port timeouts and race conditions, we start Python’s built-in HTTP server in the background and use a readiness loop to ensure the port responds before starting Playwright.

.github/workflows/playwright.yml



name: Playwright Tests CI

on:
  push:
    branches: [ main, master ]
  pull_request:
    branches: [ main, master ]

jobs:
  test:
    timeout-minutes: 60
    runs-on: ubuntu-latest

    steps:
      # 1. Pull down repository code
      - name: Checkout repository
        uses: actions/checkout@v4

      # 2. Set up Node.js runtime
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      # 3. Install project dependencies
      - name: Install dependencies
        run: npm ci

      # 4. Install Playwright browser engines and system dependencies
      - name: Install Playwright Browsers
        run: npx playwright install --with-deps chromium

      # 5. Start Python local test server in the background & poll until ready
      - name: Start dummy site server
        run: |
          python3 -m http.server 8000 --directory dummy-site &
          timeout 10 bash -c 'until curl -s [http://127.0.0.1:8000/index.html](http://127.0.0.1:8000/index.html) > /dev/null; do sleep 1; done'          

      # 6. Run Playwright tests in headless mode
      - name: Run Playwright tests
        run: npx playwright test
        env:
          CI: true

      # 7. Upload HTML reports & artifacts
      - name: Upload Test Report
        uses: actions/upload-artifact@v4
        if: ${{ !cancelled() }}
        with:
          name: playwright-report
          path: playwright-report/
          retention-days: 7

Architectural Takeaways

  1. Deterministic Readiness Gates: Arbitrary delays like sleep 2 often lead to flaky runs across different CI runner specs. A polling readiness gate using curl guarantees the server socket is accepting traffic before Playwright fires its browser contexts.
  2. Context-Aware Error Feedback: Feeding lastError back into the self-healing retry loop provides the LLM with negative feedback, preventing it from proposing the exact same non-functional selector twice.
  3. Structured JSON Output: Forcing the LLM into JSON output mode (format: 'json') eliminates unpredictable natural language conversational padding, letting test harnesses deserialize and apply locator fixes instantaneously.
